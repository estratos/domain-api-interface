# Domain API Interface 1.1.0

**Released:** 2026-10-24
**Full changelog:** [1.0.0...1.1.0](https://github.com/estratos/domain-api-interface/compare/1.0.0...1.1.0)
**Package:** `estratos/domain-api-interface:^1.1`

First maintenance release after 1.0.0. The provider contracts keep the same
methods and signatures; the release focuses on the error contract, the missing
test suite, documentation and tooling.

## Highlights

- **Test suite added** — 71 tests, 201 assertions, 23 files covering every DTO,
  request object, the `RecordType` enum, the exceptions and the bundle class.
- **Registrar-independent error contract** — `ProviderException`,
  `DomainNotFoundException` and `RequestValidationException`, with `@throws`
  documented on every contract method.
- **Failure results are simpler** — `RegistrationResult::failure()` and
  `RegistrationResult::success()` remove the need for placeholder order IDs and
  dates.
- **Static analysis and style are clean** — PHPStan 2.x at `--level=max` and
  PHP-CS-Fixer on all 54 PHP files.
- **Documentation rebuilt** — complete API reference, working examples,
  architecture diagram, testing instructions and limitations.

## Added

- `ProviderException`, `DomainNotFoundException` and `RequestValidationException`.
- `RegistrationResult::success()` and `RegistrationResult::failure()` factories.
- Canonical status constants: `TransferStatus::STATUS_*`, `DomainInfo::STATUS_ACTIVE`
  and `DomainSummary::STATUS_ACTIVE`.
- `tests/` suite (71 tests, 201 assertions) with `#[CoversClass]` metadata.
- Array shape annotations (`string[]`, `array<string, float>`) for static analysis.

## Changed

- `RegistrationResult::$orderId`, `$registrationDate` and `$expirationDate` are
  now nullable and optional.
- Status helpers in `TransferStatus`, `DomainInfo` and `DomainSummary` ignore
  case and surrounding whitespace.
- Runtime dependencies narrowed from `symfony/framework-bundle` to
  `symfony/config`, `symfony/dependency-injection` and `symfony/http-kernel`.
- PHPStan upgraded to `^2.2`; PHP-CS-Fixer configuration fixed and the codebase
  formatted.
- `phpunit.xml.dist` no longer uses the PHPUnit-9-era `<coverage><include>`
  element and no longer requests coverage reports without a coverage driver.
- `README.md` rewritten with the full API reference and runnable examples.

## Fixed

- `DomainInfo::daysUntilExpiration()` now returns a negative value for expired
  domains (`DateInterval::$days` is absolute).
- `CHANGELOG.md` contained generation artifacts (`### 31. CHANGELOG.md` and an
  unclosed code fence).
- `README.md` had an unclosed `bash` fence that rendered the rest of the
  document as code.
- `LICENSE` shipped GPL-3.0 text while the metadata declared MIT; both are now
  MIT.
- `.gitignore` targeted a Symfony 2/3 layout and missed the PHPUnit, PHPStan and
  PHP-CS-Fixer cache directories.

## Removed

- Unused `EXTENSION_ALIAS` constant in `DomainApiInterfaceBundle`.

## Upgrade notes

### `RegistrationResult` fields are nullable

Constructing a failure result no longer requires an order ID and dates:

```php
// 1.0.x
new RegistrationResult(false, 'example.com', '', $now, $now, null, 'failed');

// 1.1.0
RegistrationResult::failure('example.com', 'failed');
```

If your code reads `$result->orderId`, `$result->registrationDate` or
`$result->expirationDate`, handle `null`: those values are only guaranteed on
success. Constructor calls keep working, but this is a type-level change for
consumers that assume non-null values — adapt before upgrading if that applies
to you.

### Validation errors have a dedicated type

Request objects now throw `RequestValidationException`. It extends
`\InvalidArgumentException`, so existing `catch` blocks keep working; catching
the dedicated type is optional:

```php
use Estratos\DomainApiInterface\Exception\RequestValidationException;

try {
    new RenewDomainRequest('example.com', 11);
} catch (RequestValidationException $exception) {
    // invalid term
}
```

### Symfony dependencies narrowed

The package no longer requires `symfony/framework-bundle`. If your application
relied on it being installed transitively, require it explicitly.

### Status helpers normalize their input

Values such as `Pending`, `PENDING` or `' completed '` now match the canonical
statuses. This is a behavior change for providers that previously returned
non-canonical casing and were silently reporting `false` from `isPending()`.
